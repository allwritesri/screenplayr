## Development Guidelines

### General Conventions

- Keep code simple and readable; avoid premature abstraction.
- Write small, focused commits with clear messages.
- Do not commit secrets, credentials, or `.env` files.
- Prefer editing existing files over creating new ones.

### Git Workflow

- Use feature branches for all development work.
- Branch names should be descriptive (e.g., `feature/add-parser`, `fix/title-rendering`).
- Write commit messages in imperative mood (e.g., "Add screenplay parser" not "Added screenplay parser").

### Code Quality

- Run linting and tests before committing.
- Fix warnings and errors rather than suppressing them.
- Add tests for new functionality.
